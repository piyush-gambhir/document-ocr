# Dataset coverage for every supported document

Updated 2026-09-08. **Active accuracy evaluation uses downloaded dataset
documents only.** Four of the 15 registered profiles have labelled positive
dataset samples. Locally generated fixtures and the agent-transcribed EAD
specimen are not run by the active accuracy workflows and do not close gaps.

The [machine-readable catalog](document_dataset_coverage.json) retains source
links, terms, annotation types and small-sample plans. A linked candidate is not
an admitted sample. The [additional source review](ADDITIONAL_SOURCE_REVIEW.md)
records reference/specimen research, separate from the active dataset suite.

## Active sample

The [public manifest](public_samples.json) and [expansion](public_expansion_samples.json)
contain 62 images in 33 source-document groups: 39 labelled positives across
four profiles, seven unrelated controls and 16 unscored observations. Labels
come from publisher annotations or renderer output with reviewed mappings.
IDNet and Symage contain publisher-generated documents, and MIDV includes
fictional specimens. This is dataset-sourced evidence, not necessarily issued
personal-document evidence. No images are generated by this project for these
runs. Re-encodings, repeated requests and multiple captures do not add holders.
The small fixed sample has guided fixes and is not an independent release holdout.

## Indian passport findings

No admitted public image-and-label corpus establishes **real Indian passport
accuracy**. Generated biodata records cannot change that limitation and are
excluded from the active evaluation.

- [akashsalmuthe/ind_passport](https://huggingface.co/datasets/akashsalmuthe/ind_passport)
  advertises images/descriptions, but the inspected revision lacks verified
  dataset licensing and annotation provenance. Related repositories are not
  independent extra coverage.
- [UniData's Indian passport card](https://huggingface.co/datasets/ud-synthetic/indian-passports)
  describes a larger product, but the pinned public repository contains CSV
  metadata and a README, not images. Provider access and NC-ND terms are recorded
  in the catalog; metadata cannot be submitted to an image OCR API.
- [PRADO IND-AO-01001](https://www.consilium.europa.eu/prado/en/IND-AO-01001/index.html)
  is an official older-layout reference. Its [specific reuse restrictions](https://www.consilium.europa.eu/en/about-site/copyright/)
  keep it as a link rather than an automatically collected fixture.
- [Commons references](https://commons.wikimedia.org/wiki/Category:Passports_of_India)
  need individual licence and field review. Blank, censored or historical pages
  without verified labels cannot measure complete positive extraction accuracy.

Non-Indian passport results, simplified generated Indian layouts, and unscored
Aadhaar observations must not be reported as measured Indian population accuracy.

## Prepare a small suite and run it

Fetch only checksum-pinned dataset samples and run the core and actual HTTP API:

```bash
.venv/bin/python -m benchmarks.public_data fetch-samples
.venv/bin/python -m benchmarks.public_data fetch-samples --manifest benchmarks/public_expansion_samples.json
.venv/bin/python -m benchmarks.multidoc_accuracy --output benchmark-data/public/current.json
.venv/bin/python -m benchmarks.http_accuracy --output benchmark-data/http/current.json
```

The [HTTP runner](HTTP_EVALUATION.md) verifies uploads, PNG/JPEG/raster-PDF
encodings, hints/evidence, batch/grouped/job routes and client concurrency.
These reuse original images and truth, adding API checks rather than identities.
Before/after runs require the same samples, scorer, model files, configuration
and environment. Run them sequentially on an otherwise quiet machine; keep
failed positives in their denominators and absolute targets separate from
relative regression gates.

[Core CI](../.github/workflows/ocr-evaluation.yml) and
[public HTTP CI](../.github/workflows/ocr-http-public.yml) use downloaded datasets
only. Generated fixtures and the reviewed EAD transcription are retained as
engineering/research material, outside automatic image-accuracy evaluation.
[Current results](ALL_DOCUMENTS_EVALUATION.md) report dataset coverage and
remaining failures. [Earlier results](MULTIDOC_EVALUATION.md) are historical.

## Admitting the next samples

For public field scoring, require a usable image, documented terms and source
revision, checked field mapping to publisher annotations or verified
transcriptions, and a source-document group. For a reviewed specimen, record
who transcribed it, what remains ambiguous, and whether independent review has
occurred. Preserve that weaker label provenance in its separate report.

Start with 5–10 reviewed examples for a missing profile or important variant.
Choose samples before observing OCR results, preserve difficult and rejected
cases, and reserve different holders/layouts as a holdout after tuning. Label
missing values explicitly so hallucinated optional fields can be detected.
Blank or censored samples need rejection or partial-field expectations instead
of invented positive values. Model answers, generation prompts, detection boxes
and administrative text records cannot substitute for checked image truth.

Fetch only selected archive members or rows with pinned hashes and byte limits;
never download full datasets just to run a smoke test. The source catalog keeps
unresolved leads as links and does not automatically download them. Images,
private identity data and raw OCR responses stay under ignored `benchmark-data/`;
only permitted score/provenance reports and fixture definitions belong in Git.
